Спецификация REST API для 1С (Luxury Optic)

Интеграция каталога оправ, очковых линз, контрагентов и выгрузки заказов

1. Архитектурный подход

Используется комбинированная Pull + Push (Webhook) модель взаимодействия в реальном времени без перегрузки 1С и сайта:

  • Каталог (оправы и линзы — полная сверка): 1С публикует HTTP-сервис (REST API), сайт обращается к нему по расписанию (Pull-модель).
  • Точечное обновление остатков и цен в реал-тайме (Webhook от 1С → Сайт): При проведении заказа, продаже или оприходовании в 1С — 1С отправляет POST /api/v1/webhooks/1c/stocks/ на сайт со списком только изменившихся товаров (id_1c), чтобы сайт мгновенно обновил остатки без тяжёлого полного GET-запроса.
  • Контрагенты (Webhook от 1С → Сайт + резервный Pull): При создании/изменении контрагента 1С сразу отправляет вебхук POST /api/v1/webhooks/1c/customers/ на сайт для моментальной регистрации клиента (плюс остаётся резервный GET /api/v1/customers).
  • Заказы и защита от нулевых остатков (Push от Сайта → 1С): Сайт блокирует добавление в корзину и оформление товаров с stock ≤ 0 или при превышении остатка. При оформлении сайт отправляет POST /api/v1/orders в 1С, а 1С резервирует товар и возвращает актуальные остатки (либо ошибку 422 PRODUCT_OUT_OF_STOCK с актуальными остатками).
Общие требования: Формат данных — JSON (UTF-8). Авторизация (двусторонняя) — Authorization: Bearer <token> или Basic Auth. Даты в формате ISO 8601 (YYYY-MM-DDTHH:MM:SS). Валюта цен — UZS.

4. Контрагенты (Клиенты B2B — Вебхук + Сверка)

Для моментальной регистрации новых клиентов в B2B-кабинете и Telegram-боте используется реал-тайм вебхук от 1С к сайту, дополненный периодическим GET-запросом.

4.1. Вебхук от 1С при создании/изменении контрагента (1С → Сайт):

POST /api/v1/webhooks/1c/customers/

Вызывается 1С автоматически при записи нового контрагента или изменении его контактных данных.

{
  "items": [
    {
      "id_1c": "7ea8102b-11c2-4a01-99ee-ab012845c110",
      "company_name": "ООО «Optic Grand Tashkent»",
      "inn": "123456789",
      "is_active": true,
      "contact_person": {
        "full_name": "Азизов Азиз Азизович",
        "first_name": "Азиз",
        "last_name": "Азизов",
        "phone": "+998901234567",
        "email": "aziz@opticgrand.uz"
      }
    }
  ]
}

Ответ сайта (HTTP 200 OK):

{
  "status": "success",
  "processed": 1,
  "results": [
    {
      "id_1c": "7ea8102b-11c2-4a01-99ee-ab012845c110",
      "company_id_site": 12,
      "user_id_site": 15,
      "telegram_link_token": "c4f1d2e3-88a1-4b2c-9f00-112233445566"
    }
  ]
}

4.2. Периодическая сверка контрагентов (Сайт → 1С):

GET /api/v1/customers

Возвращает полный список активных контрагентов в том же формате {"items": [...]} для фоновой сверки.

5. Выгрузка заказов в 1С и контроль остатков

POST /api/v1/orders
Защита от заказов при отсутствии остатков: Сайт проверяет stock > 0 и quantity ≤ stock при добавлении в корзину и оформлении. В момент оформления сайт синхронно отправляет заказ в 1С. 1С проверяет остатки, проводит заказ и возвращает обновлённые остатки по позициям в массиве updated_stocks (либо возвращает 422 PRODUCT_OUT_OF_STOCK с актуальными остатками, чтобы сайт сразу обновил их у себя и не пропустил заказ).

6. Вебхук от 1С: Точечное обновление остатков и цен в реал-тайме

POST /api/v1/webhooks/1c/stocks/

Вызывается 1С при проведении заказа, офлайн-продаже, списании или оприходовании. Передаёт только изменившиеся позиции (id_1c), чтобы сайт мгновенно обновил остатки без тяжёлого полного GET-запроса всего каталога.

Тело запроса от 1С к сайту:

{
  "reason": "order_created",
  "items": [
    {
      "id_1c": "1dc92560-58c0-11f0-b0e4-ee81ce5b1c14",
      "stock": 12,
      "price": 420000.00
    },
    {
      "id_1c": "3c84636c-099c-11f0-96ec-d85ed3a775a0#e3e35f25-9dcc-11e5-8146-001e676d277d",
      "stock": 0
    }
  ]
}

Ответ сайта (HTTP 200 OK):

{
  "status": "success",
  "updated_frames": 1,
  "updated_lenses": 1,
  "not_found": []
}
